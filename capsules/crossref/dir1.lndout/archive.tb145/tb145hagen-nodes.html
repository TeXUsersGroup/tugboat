Title: Nodes and other neat old features

Summary: traditional and Lua(Meta)TeX memory layouts and processing.

Full text of article: available to TUG members (join TUG); will be publicly available after the next issue is published.

Author: Hans Hagen

Publication: TUGboat volume 47, number 1 (2026), pages 114–118

DOI (this page): 10.47397/tb/47-1/tb145hagen-nodes
(previous doi - next doi)

Category: Graphics

Difficulty: Advanced

Abstract: In TeX, nodes are an important data structure because all content is kept in (a linked list of) nodes. If we compare traditional TeX with LuaTeX there are some fundamental differences. For instance, character (glyph) nodes are larger because we have both a prev pointer and an attribute list pointer. This means that they are always larger than one memory word. We discuss this and other differences in TeX implementations.

What conclusions can we draw? First of all that in original TeX there are some clever memory management features. Second that in LuaTeX we no longer use them. A third conclusion is that in spite of what one might think, it doesn’t impact the performance of the successor; time is likely spent elsewhere. We leave it to the reader to wonder if the original TeX approach of a single pool-with-combining-features wins over the faster but maybe more spoiling pool-per-size approach of the other engines.
